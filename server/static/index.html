ARCHITECTURE DEEP DIVE

Asymmetric Multi-Agent RL Environment for Autonomous Cyber Defense

🛡 THE PROBLEM

Modern AI agents using Model Context Protocol (MCP) face tool-poisoning, prompt injection, and STDIO sandbox escapes at machine speed. Human SOC analysts can't triage fast enough. OmniGuard trains an RL agent to autonomously defend the gateway — solving the Action Calibration Gap: block too much = business downtime; block too little = catastrophic breach.

🤖 MULTI-AGENT DYNAMICS

  • Defender Agent — Qwen-2.5-3B fine-tuned via GRPO. Chooses from 6 defensive actions per step.
  • Adversarial Curriculum — Environment's PayloadMutator acts as the attacker. Dynamically escalates obfuscation, Base64, URL encoding, and recursive self-correction.
  • Semantic Critic — LLM-as-a-Judge grades SEMANTIC_DIFF actions via cosine similarity, preventing reward hacking.

📊 REWARD SIGNAL

  • +0.5 True Positive — threat neutralized
  • +0.2 True Negative — benign traffic allowed
  • -0.4 False Positive — alert fatigue penalty
  • -1.0 False Negative — catastrophic breach, episode terminates

Heavily asymmetric to prevent the "block everything" shortcut.

⚡ ENVIRONMENTAL MECHANICS

  • Recursive Self-Correction Trap — blocked threats respawn as mutated variants
  • Temporal Decay — latency budget shrinks reward if agent is too slow
  • STDIO Sandbox Escapes — only REVOKE_STDIO action can stop these; BLOCK fails
  • Adaptive Curriculum — 3 phases: bootstrapping → evasion → chained exploitation

⚔ ACTION SPACE

ACTIONDESCRIPTIONUSE CASE
ALLOWPass traffic through the gatewayVerified benign enterprise traffic
BLOCKReject and quarantine the requestKnown-pattern malicious payloads
SPOTLIGHTFlag for deeper analysis pipelineUncertain or edge-case traffic
SEMANTIC_DIFFCompare payload against known threat signatures via embeddingsObfuscated / encoded attacks
CAPABILITY_MEDIATIONRestrict tool capabilities while allowing partial executionPrivilege escalation attempts
REVOKE_STDIOSever all STDIO/TTY execution channelsSandbox escape via fork bomb / TTY hijack

💾 DATA ENGINE

  • Benign: witfoo/precinct6-cybersecurity (2M rows)
  • Malicious: AlicanKiraz0/Cybersecurity-Dataset-Fenrir-v2.1
  • Oracle: ethanolivertroy/nist-cybersecurity-training

Zero hardcoded threats. All payloads streamed live from HuggingFace datasets with prefetch queues and dynamic obfuscation.

🏅 TRAINING STACK

  • Algorithm: GRPO (Group Relative Policy Optimization) via HF TRL
  • Model: Qwen2.5-3B-Instruct + LoRA (r=64)
  • Optimization: Unsloth 4-bit quantization
  • Tracking: Weights & Biases (mean_episode_reward, false_positive_rate, curriculum_level)
  • Distributed: Accelerate + FSDP for multi-GPU scaling

OPENENV API REFERENCE

All endpoints follow the OpenEnv specification. Interactive docs also available at /docs (Swagger UI).
GET/healthz
Health check — returns status, env instance count, and queue depths.

  

  

    
    GET/info
    
OpenEnv environment specification — action space, observation space, reward range, datasets, curriculum phases.

    

  

  

    
    GET/readyz
    
Readiness probe — returns "ready" when all environment workers are healthy.

    

  

  

    
    GET/metrics
    
Aggregated telemetry — per-env curriculum level, episode count, moving average reward, false positive rate.

    

  

  

    POST/reset
    
Reset one or more environment instances. Accepts {"items":[{"env_id":0,"task_name":"demo"}]}.

  

  

    POST/step
    
Submit a batch of defense actions. Accepts {"actions":[{"env_id":0,"action_type":"ALLOW"},...]}. Returns observations, rewards, done flags.
